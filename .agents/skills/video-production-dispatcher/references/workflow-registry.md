# 视频生产工作流注册表

本注册表是调度层的路由依据。它描述“可选择的主生产工作流”，不等同于所有可复用的 Skill、工具或视频剪辑能力。

本注册表不是完整的 Skill 能力注册系统。统一 manifest、依赖解析、自动能力校验、版本兼容和弃用管理仍属于规划能力；在该链路落地前，注册表只作为人工维护的工作流路由依据。

## 当前注册条目

|---|---|---|---|---|

## 规划中但未注册

知识科普、产品宣传/测评、访谈/直播切片、音乐视频、互动视频等目前不应被调度层宣称为已实现工作流。收到此类请求时：

1. 明确告知该类型尚未注册或尚未完成实现；
2. 推荐最接近的当前条目；
3. 只有用户确认后，才使用通用或已有工作流完成有限范围的交付；
4. 在路由上下文中记录这是兼容回退，而不是原生类型支持。

## 条目字段约定

每个正式条目至少需要说明：

- `workflow_id`：稳定、唯一的路由 ID；
- `status`：`active`、`planned` 或 `deprecated`；
- 适用场景和明确不适用的边界；
- 工作流 Skill 路径及版本；
- 接受的输入、主要内部阶段和可复用能力；
- 输出如何映射到统一 `video-spec.md`；
- 用户确认点、失败回退和最低验收标准。

## 路由与注册表维护

- 新增视频类型时，先判断它是现有工作流内的类型模块、表达变体，还是具有独立输入/工具链/生命周期/质量模型的重型工作流。
- 只有后一种情况才新增顶层注册条目。
- 新条目必须先有对应工作流 Skill 和统一 `video-spec` 映射，再将状态设为 `active`。
- 调度层不得根据名称猜测不存在的工作流；注册表是唯一可宣称的支持范围。
