# Agent 驱动的自主视频生产平台总设计

## 文档定位

本文档是视频生产项目的总设计、方法论基线和扩展规范。

它规定平台的目标、核心概念、生产链路、Agent 与用户的职责边界、视频类型的扩展方式，以及 `SKILL.md`、参考文档、模板和渲染层之间的关系。

本文档不是某一部影片的 `video-spec.md`，也不是某一种视频类型的操作手册。后续新增视频类型、平台适配或生产能力时，应先检查本文档定义，再更新具体执行文件。

## 一、项目定位

平台将用户的想法、目标、内容来源和素材，编排成可执行的视频生产规格，并支持后续的分镜、渲染、审片和迭代。

本平台采用“单一默认入口、可插拔视频类型生产工作流、少量独立重型工作流”的分层架构。用户通过默认入口描述视频目标、内容和素材，调度层 Skill 自动筛选和确认一条生产工作流；对于输入、工具链、生命周期或产物显著不同的任务，允许独立工作流直接调用。

这里的“单一默认入口”是面向普通用户的主要入口，不限制高级用户直接调用独立工作流；“统一规格输出”是共享核心字段和输出契约，同时允许类型工作流增加必要的扩展字段；“统一质量边界”是共享技术和来源底线，不是强行统一所有视频类型的审美标准。

平台只有一个面向普通用户的默认入口：调度层 Skill。它负责识别用户意图、内容来源、平台目标和约束，并推荐或确认一条生产工作流。

调度层可以将任务路由到：

- **通用视频编排工作流**：用户知道想表达什么，但不确定应该做成哪种视频类型；
- **特定类型生产工作流**：例如高能混剪、影视解说、知识科普、产品测评、纪录片或微短剧；
- **独立重型工作流**：仅用于具有独特输入、专属工具链、显著不同生命周期或专属产物的任务。

高级用户可以直接调用已注册的独立重型工作流，但这不改变默认入口的统一调度职责。所有工作流最终都输出可审阅、可渲染、可迭代的 `video-spec.md`。

平台的核心价值不是替用户凭空决定内容，而是把模糊意图逐步收敛成：

```text
目标明确、类型清楚、结构成立、素材可用、剪辑可执行、平台可发布
```

## 二、Agent 自主范围与用户边界

### 2.1 Agent 可以自主完成的工作

- 识别项目、影片或内容来源，并遵守多影片目录边界；
- 从用户描述中抽取已知信息，减少重复提问；
- 作为调度层识别意图、筛选候选工作流并处理用户确认或回退；
- 在选定的生产工作流中执行该工作流定义的步骤，不强迫所有类型共享同一套中间流程；
- 根据目的、受众、内容和素材推荐视频类型、叙事结构和表达视角；
- 盘点现有素材，标记缺口，提出可生成或待搜索的素材；
- 将类型规则转换为文案、节奏、剪辑和分镜要求；
- 生成或更新 `edit-plan.md` 与 `video-spec.md`；
- 执行确定性的规格、路径、时长、字段和平台检查；
- 根据用户审片反馈进入迭代模式，分析受影响的场景和依赖。

### 2.2 用户必须保留的决策

- 核心观点、事实立场和主要卖点；
- 目标受众和主要平台；
- 关键内容取舍；
- 在候选类型、结构和视角之间的最终选择；
- 重要素材是否可以使用；
- 风格参考、禁用方向和品牌边界；
- 对渲染预览的最终审片判断。

“自主”表示 Agent 能够自主编排和推进工作，不表示 Agent 可以默默替用户做关键创意决策。

## 三、核心概念

### 3.1 视频目的

视频希望达成的结果，例如让观众理解、共情、购买、追更、讨论或参与。目的不是“想火”“高级”这类模糊结果。

### 3.2 内容领域

内容所在领域，例如电影、产品、知识、品牌、体育、生活或社会议题。内容领域决定事实资料和素材来源，不等于视频类型。

### 3.3 视频类型

一种可以重复使用的内容产品形态，规定视频通常如何吸引观众、组织内容和产生观看行为。

示例：

- 高能混剪；
- 影视解说；
- 知识科普；
- 热点评论；
- 盘点与榜单；
- 真实故事与纪录片；
- Vlog 与幕后；
- 产品测评与开箱；
- 教程与技能演示；
- 剧情短剧与微短剧；
- 悬疑调查与反转；
- 情绪品牌片；
- 反应、评论与粉丝二创；
- 直播或访谈切片；
- 音乐、舞蹈与挑战；
- 互动、AI 与虚拟角色。

视频类型是本平台的主要扩展单位。

### 3.4 叙事结构

内容如何安排信息和冲突，例如线性三幕、结果先行、问题驱动、调查揭示、人物成长、平行蒙太奇、连载悬念或开放共创。

### 3.5 表达视角

观众通过谁来理解内容，例如第一人称、旁白上帝视角、主持人、角色视角、观察者、多人物或用户代理人。

### 3.6 文案策略

文案如何承载信息和情绪，例如讲故事、解释观点、提出问题、展示证据、制造悬念、提供步骤或推动行动。

### 3.7 剪辑语法

剪辑如何把内容变成观看体验，包括镜头密度、镜头顺序、节拍、素材角色、字幕、转场、音效、画面运动和信息释放方式。

### 3.8 平台上下文与平台目标

平台上下文是前置约束，包括画幅、时长、观看场景、静音比例和安全区。

平台目标是观看行为目标，包括完播、收藏、评论、转发、点击、购买、追更或参与。

二者不能混为一个字段。

### 3.9 视觉主题

颜色、字体、装饰、组件和动效的视觉系统。视觉主题是内容设计的视觉层，不能代替视频类型、叙事结构或剪辑语法。

### 3.10 `video-spec` 契约

`video-spec` 是生产工作流向审核层、执行层和迭代层交付的共同接口，不是要求所有工作流填写完全相同的创意模板，也不只是给 HyperFrames 的剪辑提示词。

契约由两部分组成：

- **共享核心字段**：项目目标、受众、平台与时长、叙事和分镜时间轴、素材引用、字幕与音频、视觉规则、渲染参数、来源与风险、待确认项、版本和验收信息；
- **类型扩展字段**：由具体生产工作流定义的规则和数据，例如节拍点、论点证据、卖点演示步骤、分支状态或类型专属验收指标。

`video-spec.md` 是契约的文档化载体。不同工作流可以拥有不同的提问顺序和内部产物，但必须将结果映射为共享核心字段与类型扩展字段，使后续审核、渲染和迭代能够理解。

## 四、总体架构

### 架构分层与运行时职责

平台采用以下六层结构：

1. **调度层**：识别用户意图、内容来源、平台目标和约束，推荐或确认生产工作流；
2. **生产工作流层**：执行通用编排、特定类型或独立重型工作流定义的创作步骤；
3. **规格契约层**：将工作流结果整理为统一核心字段和类型扩展字段，形成 `video-spec.md`；
4. **审核与门禁层**：执行自动规格校验、独立只读审核和可配置的人工确认；
5. **执行与渲染层**：由 HyperFrames 等执行工具读取规格，生成视频产物并执行渲染后检查；
6. **人工反馈闭环**：用户观看成片，提出修改意见，Agent 回到受影响的工作流或规格阶段迭代。

平台级运行时链路固定为：

```text
用户
    ↓
调度层 Skill：意图识别与工作流路由
    ↓
一条主生产工作流
    ↓
video-spec.md
    ↓
自动规格校验 + 独立只读审核
    ↓
人工确认门（可按策略跳过）
    ↓
HyperFrames 等执行 / 渲染层
    ↓
渲染产物自动检查
    ↓
人工审片与迭代
    ↓
回到工作流或规格阶段
```

人工确认可以按项目风险和用户授权跳过，但必要的自动规格校验、渲染前门禁和渲染后产物检查不可跳过。视觉主题、平台适配和素材能力由选定工作流调用，不应被调度层误认为另一条生产工作流。

### 调度层路由规则

- 用户明确提出视频类型时，调度层优先匹配对应的生产工作流；
- 用户只描述目标、内容或素材时，调度层推荐候选工作流，必要时请求用户确认；
- 没有匹配类型或用户无法判断时，回退到通用视频编排工作流；
- 任务具有独特输入、工具链、生命周期或产物边界时，路由到独立重型工作流；
- 默认只选择一条主生产工作流，TTS、字幕、素材搜索、音频混音等作为该工作流可调用的共享能力或子流程；
- 用户可以覆盖 Agent 的推荐，但覆盖后仍需执行所选工作流的契约和门禁检查。

## 五、平台级生产链路与创作映射

所有工作流最终都需要映射到以下创作决策维度，但不同工作流可以拥有不同的提问顺序、内部阶段和生产方式：

```text
视频类型
→ 叙事结构
→ 表达视角
→ 文案策略
→ 剪辑语法
→ 平台目标
→ 分镜与素材规格
```

平台运行时顺序为：

```text
用户输入
→ 调度层识别意图、上下文与约束
→ 推荐或确认一条主生产工作流
→ 生产工作流执行自身的创作步骤
→ 映射为统一 video-spec 契约
→ 自动规格校验与独立只读审核
→ 人工确认或按策略跳过
→ 执行层读取规格并渲染
→ 渲染产物自动检查
→ 人工审片与迭代
```

通用模式不等于缺省叙事设计。即使用户不知道类型，也必须通过追问或推荐补齐上述创作决策维度；无法确认的部分应保留为显式待确认项。

在这条链路开始前，Agent 需要确认：

- 内容来源和项目边界；
- 视频目的；
- 目标受众；
- 主平台和时长；
- 核心信息；
- 已有素材和素材限制。

这部分是上下文，不是视频类型本身。

## 六、通用编排模式

### 6.1 适用场景

用户只描述了主题、目标或素材，不确定视频类型，或者认为多种类型都可以。

### 6.2 工作方式

Agent 不强迫用户学习类型术语，而是从以下信息出发：

```text
目的 + 受众 + 内容 + 素材 + 平台 + 希望观众产生的行为
```

然后推荐一条或两条可执行路径，例如：

```text
类型：通用编排
结构：问题驱动
视角：旁白 + 现场素材
文案：问题、证据、结论
剪辑：口播主线 + B-roll + 关键词字幕
平台目标：完播与收藏
```

通用模式可以产生类型假设，但假设必须标记为推荐或待用户确认，不能伪装成用户已经决定的内容。

通用模式不应因为缺少类型名称而省略叙事设计。它需要通过追问或推荐补齐结构、视角、文案和剪辑决策；无法确认的部分应保留为显式待确认项。

### 6.3 通用模式的底线

- 不因用户不知道类型而停滞；
- 不因为没有类型选择而默默套用某个类型；
- 不把通用模式退化成空泛的“自由发挥”；
- 仍然必须落到结构、视角、文案和剪辑决策。

## 七、特定类型生产工作流

### 7.1 类型工作流的作用

特定类型工作流把一种常见视频形态的经验固化为可执行的生产路径。它负责自己的提问顺序、叙事规划、文案生产、素材组织、剪辑决策和类型验收，不要求与其他类型共享相同的中间阶段。工作流可以复用素材解析、研究、TTS、字幕、音频和渲染等底层能力，但必须通过统一 `video-spec` 契约交付结果。

### 7.2 类型工作流必须定义的内容

每新增一种类型，至少补齐：

```text
类型定义
适用场景
不适用场景
用户输入问题
默认叙事结构
可选表达视角
文案策略
素材组织方式
剪辑语法
节奏 profile
字幕与音频规则
平台适配
常见失败模式
类型专属验收标准
```

工作流注册信息至少应包含：工作流 ID、适用和不适用场景、必需输入、内部阶段、可复用能力调用、`video-spec` 映射规则、类型扩展字段、验收标准，以及无法适用时的回退或澄清规则。类型差异较小时可以复用同一实现并通过配置扩展；差异较大时应作为独立生产工作流维护，不能让调度层或通用工作流偷偷承担其全部逻辑。

### 7.3 类型工作流的推荐说明格式

类型工作流说明应能回答：

1. 这是什么视频，观众为什么会看？
2. 开头如何让观众留下？
3. 中间如何推进信息、冲突或情绪？
4. 结尾如何完成回报或推动下一步？
5. 需要什么素材，缺少素材时怎么办？
6. 剪辑时哪些手段是核心，哪些手段应避免？
7. 如何判断成片仍然属于这种类型？

## 八、生产方式分流

视频类型和生产方式不是同一个概念。同一类型可能有不同生产方式，不同类型也可能共享生产方式。

平台至少支持以下生产方式：

```text
script-led       文案驱动
asset-led        素材驱动
character-led    人物驱动
capture-led      现场或直播驱动
interactive-led  互动机制驱动
```

典型关系：

| 视频类型 | 常见生产方式 |
|---|---|
| 影视解说、科普、教程 | script-led |
| 高能混剪、赛事集锦 | asset-led |
| 纪录片、真实故事、Vlog | character-led |
| 直播切片、访谈 | capture-led |
| 挑战、互动剧情、AI共创 | interactive-led |

因此，“是否有逐字稿”不应成为所有视频的统一前置条件。

视频类型回答“成片应该如何叙事和表达”，生产方式回答“任务需要什么输入、工具链和生产生命周期”。调度层先选择一条主生产工作流，生产方式通常作为该工作流内部的策略；只有当某种生产方式使输入、工具链、生命周期或产物质量模型发生显著变化时，才注册为独立重型工作流或工作流变体，避免把每个标签都膨胀成独立 Skill。

## 九、平台适配

### 9.1 平台硬约束

- 画幅和安全区；
- 时长上限；
- 帧率和输出格式；
- 字幕可读性；
- 无声播放可理解性；
- 素材版权和平台发布限制。

### 9.2 平台观看行为

- 观众为什么停留；
- 观众在什么场景观看；
- 主要追求完播、收藏、评论、转发、点击还是追更；
- 是否需要循环结尾；
- 是否需要切出多个短版本；
- 是否需要不同平台的重剪。

### 9.3 类型与平台的关系

平台不应重新定义视频类型，而应调整类型的执行参数。

例如同样是影视解说：

- 抖音版本：结果或冲突前置，节奏更快，字幕更强；
- B 站版本：保留背景和论证，增加章节和上下文；
- YouTube 长视频：允许更完整的调查和人物分析。

## 十、素材、研究与参考资料

### 10.1 原始素材

用户提供的正片、录音、图片、直播文件、字幕、图形和模型。它们是视频内容的输入，保留原始路径，不擅自替换。

### 10.2 事实资料

为了理解内容或核验事实而检索的影片资料、产品资料、行业资料和公开研究。事实资料必须记录来源、日期、层级和状态。

### 10.3 风格参考

用户提供、用户点名或 Agent 推荐的作品、品牌案例、视频链接、截图和静态画面。它们用于说明风格，不自动成为剪辑素材。

### 10.4 没有参考视频时的处理

参考视频不是强制输入。

如果用户没有提供参考视频：

- 可以使用所选视频类型的默认规则；
- 可以从用户提供的正片中分析其本身的画面和叙事特征；
- 只有在用户需要风格校准时，才推荐外部案例；
- 不应因为缺少参考视频而阻止 0-1 流程。

## 十一、文案、剪辑和分镜的映射

前面的内容决策必须能够逐层传递到分镜：

```text
类型决定默认结构范围
结构决定信息顺序
视角决定谁来讲
文案决定听到什么
剪辑语法决定看到什么、何时切换
平台目标决定节奏和结尾动作
分镜把这些决策落到每一镜
```

每个 Scene 至少应能追溯到：

- 它在叙事结构中的职责；
- 它承载的信息或情绪；
- 它服务的观众行为；
- 它使用的素材；
- 它采用的剪辑规则；
- 它对应的组件和音频触发点。

## 十二、视觉主题的职责

视觉主题属于内容执行后的视觉系统，不负责决定：

- 视频是什么类型；
- 故事如何展开；
- 谁来讲述；
- 旁白如何组织；
- 镜头为什么存在。

视觉主题负责统一：

- 颜色；
- 字体和字重；
- 装饰密度；
- 组件风格；
- 动效和转场的视觉表现。

因此，类型工作流和视觉主题可以独立扩展，再在项目中组合。

## 十三、质量控制与人工审片

平台质量边界分为三层：

1. 全平台共享的技术与来源底线，例如时长、音视频完整性、字幕可读性、素材来源记录和规格字段完整性；
2. 各视频类型自己的结构、节奏、表达和平台适配标准；
3. 用户对创意质量、情绪效果和最终可发布性的人工判断。

### 13.1 Agent 的自动检查

自动检查适合确定性问题，并分为渲染前规格校验和渲染后产物检查：

- 字段是否完整；
- 时间码和总时长是否一致；
- 素材路径是否存在；
- 画幅、帧率和平台是否匹配；
- 字幕是否超出安全区；
- 音效时间点是否对应分镜；
- 组件 ID 是否真实；
- 生产工作流的硬性规则是否满足。

规格校验不通过时，不能进入渲染；渲染后产物检查不通过时，不能进入最终发布判断。

### 13.2 独立只读规格审核

独立只读审核 Agent 只检查，不直接修改工作流产物。它负责审计 `video-spec` 是否符合统一契约、所选生产工作流的类型规则、素材和来源边界、平台约束以及待确认项处理方式，并输出问题清单和通过状态。

审核 Agent 不替代用户做最终创意决策，也不应偷偷改写视频类型、叙事方向或核心观点。

### 13.3 人工确认门

人工确认门用于让用户决定是否接受当前规格并开始渲染。低风险项目可以在用户明确授权或预设策略允许时跳过人工确认，但必须记录跳过状态；必要的自动规格校验、渲染前门禁和渲染后产物检查不可跳过。

### 13.4 渲染后产物检查

渲染完成后，自动检查视频文件是否成功生成，以及时长、音视频完整性、画幅、帧率、字幕安全区、输出路径和版本标记是否符合 `video-spec`。

### 13.5 人工审片

以下问题必须由人观看和判断：

- 开头是否真的让人想看下去；
- 叙事是否清楚；
- 信息是否过载或不足；
- 节奏是否符合这类视频；
- 情绪是否成立；
- 视频是否仍然像它声明的类型；
- 观众是否会产生预期行动；
- 画面、声音和文案是否形成整体体验。

### 13.6 标准闭环

```text
生成 video-spec
→ 自动规格校验与独立只读审核
→ 人工确认或按策略跳过
→ 渲染预览
→ 渲染后产物自动检查
→ 用户人工观看
→ 用户给出问题或修改意见
→ Agent 分析影响范围
→ 更新 spec
→ 生成新版本
```

自动检查是辅助，不替代人工审片。

## 十四、迭代与变更分级

### 14.1 轻度变更

只影响局部表达：

- 字幕文案；
- 旁白措辞；
- accent 色；
- 装饰密度；
- 小范围时长。

### 14.2 中度变更

影响局部分镜和素材：

- 增删场景；
- 替换组件；
- 重排一段内容；
- 增删音效或 B-roll。

### 14.3 重度变更

改变视频的创作逻辑：

- 主视频类型变化；
- 叙事结构变化；
- 表达视角变化；
- 生产方式变化；
- 目标受众变化；
- 核心信息变化；
- 主要平台或平台目标变化。

例如：

```text
影视解说 → 高能混剪
纪录片 → 剧情短剧
第一人称 → 旁白上帝视角
线性结构 → 调查结构
```

这些变化需要重新检查文案、素材排序、节奏、字幕、音频和分镜，不能当作普通换镜头处理。

## 十五、文件与职责关系

### 15.1 总设计文档

本文档负责项目定位、核心模型、扩展契约和长期边界。

### 15.2 `SKILL.md`

调度层 Skill 负责默认用户入口、意图识别、上下文收集、工作流路由、用户确认和回退；各生产工作流 Skill 负责自己的启动检查、提问顺序、创作步骤、能力调用、文件边界和不可违反的类型约束。

### 15.3 `references/`

负责工作流、追问规则、类型规则、节奏规则、分镜拆解、组件目录和校验细节。

### 15.4 `templates/video-spec-template.md`

负责统一输出结构。

### 15.5 `video-spec.md`

负责单个影片或视频项目的具体执行规格。

### 15.6 `edit-plan.md`

负责在最终 spec 之前承载可审阅的内容拆解、剪辑计划和变更记录。

### 15.7 HyperFrames

负责根据已确认的规格执行渲染，不负责替用户重新决定视频类型和叙事方向。

当前 `video-spec-builder-personal` 是第二层的一条影片素材驱动视频生产工作流，承载当前项目的个人工作流和影片适配逻辑；它不是调度层，也不是平台最终唯一的实现边界。后续可在不破坏默认入口和输出契约的前提下，逐步增加其他生产工作流，并将独立重型工作流作为可选直接调用入口。

## 十六、新增视频类型的维护流程

新增类型时，应按以下顺序：

```text
1. 在本文档中确认类型的定位和边界
2. 定义该类型生产工作流的输入、阶段和输出字段
3. 补充类型专属追问和方案引导
4. 补充结构、节奏、素材和剪辑规则
5. 补充类型专属验收标准
6. 检查通用模式是否仍然可用
7. 检查模板、spec 规则和迭代规则是否需要同步
8. 用一个真实案例验证从需求到分镜的完整链路
```

新增类型不能只增加一个名称或标签，必须能指导实际生产；如果它具有独特输入、工具链、生命周期或产物质量模型，还应明确是否升级为独立重型工作流。

每个新类型至少应沿以下链路登记和维护：

```text
类型名称与适用场景
→ 叙事结构
→ 表达视角
→ 文案策略
→ 剪辑语法
→ 平台目标
→ 类型专属提问
→ 类型验收标准
→ 对统一 video-spec 的扩展字段
```

同时必须提供一个最小真实案例和通用模式回退规则，避免新增类型破坏默认入口。

## 十七、反偏离原则

- 不把视频目的当成视频类型；
- 不把视觉场景组件当成视频类型；
- 不强迫所有项目使用同一种叙事结构；
- 不强迫所有项目先提供逐字稿；
- 不把参考视频当成必需素材；
- 不把电影正片和风格参考混为一谈；
- 不把某个类型的规则误写成全局硬规则；
- 不用特效、转场和高密度字幕掩盖叙事缺陷；
- 不让 Agent 默默替用户决定核心内容；
- 不把自动技术检查说成创意质量结论；
- 不因用户不知道类型而停止生产；
- 不因新增类型而破坏通用编排能力。

## 十八、当前阶段的架构结论

本项目的目标架构是：

```text
用户
  ↓
调度层 Skill：意图识别与工作流路由
  ↓
一条主生产工作流
  ↓
统一 video-spec 契约
  ↓
自动校验、独立只读审核与可配置人工确认
  ↓
HyperFrames 等执行 / 渲染层
  ↓
渲染产物检查
  ↓
人工审片与迭代
```

平台共享的是调度协议、`video-spec` 契约、技术与来源质量底线、审核门禁和执行接口，不是所有视频的相同创作步骤、扁平字段或审美结果。

所有生产工作流最终都应将自己的创作结果映射到以下决策维度：

```text
视频类型
→ 叙事结构
→ 表达视角
→ 文案策略
→ 剪辑语法
→ 平台目标
→ 分镜与素材规格
```

这是一套统一的语义映射和规格要求，不代表所有工作流必须按相同顺序执行。

当前实现与目标架构需要明确区分：现阶段 `video-spec-builder-personal` 是一条影片素材驱动的生产工作流，通用编排和影片适配主要在其内部承载；独立调度层、更多类型生产工作流和重型工作流仍按注册协议逐步建设。本文档描述的是目标架构与长期边界，不假设所有工作流已经完成。
