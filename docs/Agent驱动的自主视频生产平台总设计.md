# Agent 驱动的自主视频生产平台总设计

## 文档定位

本文档是视频生产项目的总设计、方法论基线和扩展规范。

它规定平台的目标、核心概念、生产链路、Agent 与用户的职责边界、视频类型的扩展方式，以及 `SKILL.md`、参考文档、模板和渲染层之间的关系。

本文档不是某一部影片的 `video-spec.md`，也不是某一种视频类型的操作手册。后续新增视频类型、平台适配或生产能力时，应先检查本文档定义，再更新具体执行文件。

## 一、项目定位

平台将用户的想法、目标、内容来源和素材，编排成可执行的视频生产规格，并支持后续的分镜、渲染、审片和迭代。

平台支持两类入口：

- **通用视频编排**：用户知道想表达什么，但不确定应该做成哪种视频类型。
- **特定类型工作流**：用户明确提出高能混剪、影视解说、产品测评、纪录片、微短剧等类型。

两类入口最终都输出同一种标准化结果：可审阅、可渲染、可迭代的 `video-spec.md`。

平台的核心价值不是替用户凭空决定内容，而是把模糊意图逐步收敛成：

```text
目标明确、类型清楚、结构成立、素材可用、剪辑可执行、平台可发布
```

## 二、Agent 自主范围与用户边界

### 2.1 Agent 可以自主完成的工作

- 识别项目、影片或内容来源，并遵守多影片目录边界；
- 从用户描述中抽取已知信息，减少重复提问；
- 判断使用通用模式还是特定类型模式；
- 根据目的、受众、内容和素材推荐视频类型、叙事结构和表达视角；
- 盘点现有素材，标记缺口，提出可生成或待搜索的素材；
- 将类型规则转换为文案、节奏、剪辑和分镜要求；
- 生成或更新 `edit-plan.md` 与 `video-spec.md`；
- 执行确定性的规格、路径、时长、字段和平台检查；
- 根据用户审片反馈进入迭代模式，分析受影响的场景和依赖。

### 2.2 用户必须保留的决策

- 核心观点、事实立场和主要卖点；
- 目标受众和主要平台；
- 关键内容取舍；
- 在候选类型、结构和视角之间的最终选择；
- 重要素材是否可以使用；
- 风格参考、禁用方向和品牌边界；
- 对渲染预览的最终审片判断。

“自主”表示 Agent 能够自主编排和推进工作，不表示 Agent 可以默默替用户做关键创意决策。

## 三、核心概念

### 3.1 视频目的

视频希望达成的结果，例如让观众理解、共情、购买、追更、讨论或参与。目的不是“想火”“高级”这类模糊结果。

### 3.2 内容领域

内容所在领域，例如电影、产品、知识、品牌、体育、生活或社会议题。内容领域决定事实资料和素材来源，不等于视频类型。

### 3.3 视频类型

一种可以重复使用的内容产品形态，规定视频通常如何吸引观众、组织内容和产生观看行为。

示例：

- 高能混剪；
- 影视解说；
- 知识科普；
- 热点评论；
- 盘点与榜单；
- 真实故事与纪录片；
- Vlog 与幕后；
- 产品测评与开箱；
- 教程与技能演示；
- 剧情短剧与微短剧；
- 悬疑调查与反转；
- 情绪品牌片；
- 反应、评论与粉丝二创；
- 直播或访谈切片；
- 音乐、舞蹈与挑战；
- 互动、AI 与虚拟角色。

视频类型是本平台的主要扩展单位。

### 3.4 叙事结构

内容如何安排信息和冲突，例如线性三幕、结果先行、问题驱动、调查揭示、人物成长、平行蒙太奇、连载悬念或开放共创。

### 3.5 表达视角

观众通过谁来理解内容，例如第一人称、旁白上帝视角、主持人、角色视角、观察者、多人物或用户代理人。

### 3.6 文案策略

文案如何承载信息和情绪，例如讲故事、解释观点、提出问题、展示证据、制造悬念、提供步骤或推动行动。

### 3.7 剪辑语法

剪辑如何把内容变成观看体验，包括镜头密度、镜头顺序、节拍、素材角色、字幕、转场、音效、画面运动和信息释放方式。

### 3.8 平台上下文与平台目标

平台上下文是前置约束，包括画幅、时长、观看场景、静音比例和安全区。

平台目标是观看行为目标，包括完播、收藏、评论、转发、点击、购买、追更或参与。

二者不能混为一个字段。

### 3.9 视觉主题

颜色、字体、装饰、组件和动效的视觉系统。视觉主题是内容设计的视觉层，不能代替视频类型、叙事结构或剪辑语法。

## 四、总体架构

平台由以下层组成：

```text
项目上下文
    ↓
模式判断：通用 / 特定类型
    ↓
视频类型路由
    ↓
叙事设计：结构 / 视角 / 信息释放 / 情绪曲线
    ↓
内容与素材策略：文案 / 素材 / 研究 / 缺口
    ↓
执行策略：节奏 / 字幕 / 音频 / 动效 / 转场
    ↓
分镜与音频时间轴
    ↓
渲染预览
    ↓
自动技术检查 + 人工审片
    ↓
迭代更新
```

视觉主题和平台适配贯穿这条链路，但不应改变内容类型的基本定义。

## 五、标准生产链路

核心创作链路固定为：

```text
视频类型
→ 叙事结构
→ 表达视角
→ 文案策略
→ 剪辑语法
→ 平台目标
→ 分镜与素材规格
```

在这条链路开始前，Agent 需要确认：

- 内容来源和项目边界；
- 视频目的；
- 目标受众；
- 主平台和时长；
- 核心信息；
- 已有素材和素材限制。

这部分是上下文，不是视频类型本身。

## 六、通用编排模式

### 6.1 适用场景

用户只描述了主题、目标或素材，不确定视频类型，或者认为多种类型都可以。

### 6.2 工作方式

Agent 不强迫用户学习类型术语，而是从以下信息出发：

```text
目的 + 受众 + 内容 + 素材 + 平台 + 希望观众产生的行为
```

然后推荐一条或两条可执行路径，例如：

```text
类型：通用编排
结构：问题驱动
视角：旁白 + 现场素材
文案：问题、证据、结论
剪辑：口播主线 + B-roll + 关键词字幕
平台目标：完播与收藏
```

通用模式可以产生类型假设，但假设必须标记为推荐或待用户确认，不能伪装成用户已经决定的内容。

### 6.3 通用模式的底线

- 不因用户不知道类型而停滞；
- 不因为没有类型选择而默默套用某个类型；
- 不把通用模式退化成空泛的“自由发挥”；
- 仍然必须落到结构、视角、文案和剪辑决策。

## 七、特定类型模式

### 7.1 类型模块的作用

特定类型模块把一种常见视频形态的经验固化成可复用工作流。模块不替代平台核心流程，而是为核心流程提供默认值、问题分流、规则和验收标准。

### 7.2 类型模块必须包含的内容

每新增一种类型，至少补齐：

```text
类型定义
适用场景
不适用场景
用户输入问题
默认叙事结构
可选表达视角
文案策略
素材组织方式
剪辑语法
节奏 profile
字幕与音频规则
平台适配
常见失败模式
类型专属验收标准
```

### 7.3 类型模块的推荐格式

类型模块应能回答：

1. 这是什么视频，观众为什么会看？
2. 开头如何让观众留下？
3. 中间如何推进信息、冲突或情绪？
4. 结尾如何完成回报或推动下一步？
5. 需要什么素材，缺少素材时怎么办？
6. 剪辑时哪些手段是核心，哪些手段应避免？
7. 如何判断成片仍然属于这种类型？

## 八、生产方式分流

视频类型和生产方式不是同一个概念。同一类型可能有不同生产方式，不同类型也可能共享生产方式。

平台至少支持以下生产方式：

```text
script-led       文案驱动
asset-led        素材驱动
character-led    人物驱动
capture-led      现场或直播驱动
interactive-led  互动机制驱动
```

典型关系：

| 视频类型 | 常见生产方式 |
|---|---|
| 影视解说、科普、教程 | script-led |
| 高能混剪、赛事集锦 | asset-led |
| 纪录片、真实故事、Vlog | character-led |
| 直播切片、访谈 | capture-led |
| 挑战、互动剧情、AI共创 | interactive-led |

因此，“是否有逐字稿”不应成为所有视频的统一前置条件。

## 九、平台适配

### 9.1 平台硬约束

- 画幅和安全区；
- 时长上限；
- 帧率和输出格式；
- 字幕可读性；
- 无声播放可理解性；
- 素材版权和平台发布限制。

### 9.2 平台观看行为

- 观众为什么停留；
- 观众在什么场景观看；
- 主要追求完播、收藏、评论、转发、点击还是追更；
- 是否需要循环结尾；
- 是否需要切出多个短版本；
- 是否需要不同平台的重剪。

### 9.3 类型与平台的关系

平台不应重新定义视频类型，而应调整类型的执行参数。

例如同样是影视解说：

- 抖音版本：结果或冲突前置，节奏更快，字幕更强；
- B 站版本：保留背景和论证，增加章节和上下文；
- YouTube 长视频：允许更完整的调查和人物分析。

## 十、素材、研究与参考资料

### 10.1 原始素材

用户提供的正片、录音、图片、直播文件、字幕、图形和模型。它们是视频内容的输入，保留原始路径，不擅自替换。

### 10.2 事实资料

为了理解内容或核验事实而检索的影片资料、产品资料、行业资料和公开研究。事实资料必须记录来源、日期、层级和状态。

### 10.3 风格参考

用户提供、用户点名或 Agent 推荐的作品、品牌案例、视频链接、截图和静态画面。它们用于说明风格，不自动成为剪辑素材。

### 10.4 没有参考视频时的处理

参考视频不是强制输入。

如果用户没有提供参考视频：

- 可以使用所选视频类型的默认规则；
- 可以从用户提供的正片中分析其本身的画面和叙事特征；
- 只有在用户需要风格校准时，才推荐外部案例；
- 不应因为缺少参考视频而阻止 0-1 流程。

## 十一、文案、剪辑和分镜的映射

前面的内容决策必须能够逐层传递到分镜：

```text
类型决定默认结构范围
结构决定信息顺序
视角决定谁来讲
文案决定听到什么
剪辑语法决定看到什么、何时切换
平台目标决定节奏和结尾动作
分镜把这些决策落到每一镜
```

每个 Scene 至少应能追溯到：

- 它在叙事结构中的职责；
- 它承载的信息或情绪；
- 它服务的观众行为；
- 它使用的素材；
- 它采用的剪辑规则；
- 它对应的组件和音频触发点。

## 十二、视觉主题的职责

视觉主题属于内容执行后的视觉系统，不负责决定：

- 视频是什么类型；
- 故事如何展开；
- 谁来讲述；
- 旁白如何组织；
- 镜头为什么存在。

视觉主题负责统一：

- 颜色；
- 字体和字重；
- 装饰密度；
- 组件风格；
- 动效和转场的视觉表现。

因此，类型工作流和视觉主题可以独立扩展，再在项目中组合。

## 十三、质量控制与人工审片

### 13.1 Agent 的自动检查

自动检查适合确定性问题：

- 字段是否完整；
- 时间码和总时长是否一致；
- 素材路径是否存在；
- 画幅、帧率和平台是否匹配；
- 字幕是否超出安全区；
- 音效时间点是否对应分镜；
- 组件 ID 是否真实；
- 类型模块的硬性规则是否满足。

### 13.2 人工审片

以下问题必须由人观看和判断：

- 开头是否真的让人想看下去；
- 叙事是否清楚；
- 信息是否过载或不足；
- 节奏是否符合这类视频；
- 情绪是否成立；
- 视频是否仍然像它声明的类型；
- 观众是否会产生预期行动；
- 画面、声音和文案是否形成整体体验。

### 13.3 标准闭环

```text
生成 video-spec
→ 渲染预览
→ 用户人工观看
→ 用户给出问题或修改意见
→ Agent 分析影响范围
→ 更新 spec
→ 生成新版本
```

自动检查是辅助，不替代人工审片。

## 十四、迭代与变更分级

### 14.1 轻度变更

只影响局部表达：

- 字幕文案；
- 旁白措辞；
- accent 色；
- 装饰密度；
- 小范围时长。

### 14.2 中度变更

影响局部分镜和素材：

- 增删场景；
- 替换组件；
- 重排一段内容；
- 增删音效或 B-roll。

### 14.3 重度变更

改变视频的创作逻辑：

- 主视频类型变化；
- 叙事结构变化；
- 表达视角变化；
- 生产方式变化；
- 目标受众变化；
- 核心信息变化；
- 主要平台或平台目标变化。

例如：

```text
影视解说 → 高能混剪
纪录片 → 剧情短剧
第一人称 → 旁白上帝视角
线性结构 → 调查结构
```

这些变化需要重新检查文案、素材排序、节奏、字幕、音频和分镜，不能当作普通换镜头处理。

## 十五、文件与职责关系

### 15.1 总设计文档

本文档负责项目定位、核心模型、扩展契约和长期边界。

### 15.2 `SKILL.md`

负责运行时入口、启动检查、对话原则、能力激发、文件边界和不可违反的行为约束。

### 15.3 `references/`

负责工作流、追问规则、类型规则、节奏规则、分镜拆解、组件目录和校验细节。

### 15.4 `templates/video-spec-template.md`

负责统一输出结构。

### 15.5 `video-spec.md`

负责单个影片或视频项目的具体执行规格。

### 15.6 `edit-plan.md`

负责在最终 spec 之前承载可审阅的内容拆解、剪辑计划和变更记录。

### 15.7 HyperFrames

负责根据已确认的规格执行渲染，不负责替用户重新决定视频类型和叙事方向。

## 十六、新增视频类型的维护流程

新增类型时，应按以下顺序：

```text
1. 在本文档中确认类型的定位和边界
2. 定义该类型的完整模块字段
3. 补充类型专属追问和方案引导
4. 补充结构、节奏、素材和剪辑规则
5. 补充类型专属验收标准
6. 检查通用模式是否仍然可用
7. 检查模板、spec 规则和迭代规则是否需要同步
8. 用一个真实案例验证从需求到分镜的完整链路
```

新增类型不能只增加一个名称或标签，必须能指导实际生产。

## 十七、反偏离原则

- 不把视频目的当成视频类型；
- 不把视觉场景组件当成视频类型；
- 不强迫所有项目使用同一种叙事结构；
- 不强迫所有项目先提供逐字稿；
- 不把参考视频当成必需素材；
- 不把电影正片和风格参考混为一谈；
- 不把某个类型的规则误写成全局硬规则；
- 不用特效、转场和高密度字幕掩盖叙事缺陷；
- 不让 Agent 默默替用户决定核心内容；
- 不把自动技术检查说成创意质量结论；
- 不因用户不知道类型而停止生产；
- 不因新增类型而破坏通用编排能力。

## 十八、当前阶段的架构结论

本项目的稳定核心是一个可扩展的 Agent 编排框架：

```text
通用编排核心
    + 特定视频类型模块
    + 内容来源适配器
    + 平台适配器
    + 视觉主题系统
    + 素材与研究系统
    + HyperFrames 渲染执行
    + 人工审片与迭代闭环
```

其中，所有特定类型都必须遵守同一条生产链路：

```text
视频类型
→ 叙事结构
→ 表达视角
→ 文案策略
→ 剪辑语法
→ 平台目标
```

用户不确定类型时，平台回退到通用编排模式；用户明确类型时，平台加载对应模块；未来新增类型时，只扩展模块，不改变核心链路。
