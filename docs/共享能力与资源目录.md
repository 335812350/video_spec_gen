# 共享能力与资源目录

> 状态：active
> 用途：为调度层、生产工作流和维护者提供共享能力索引
> 最后核对：2026-09-02

## 1. 定位与职责

本目录只说明项目已经能复用什么、从哪里进入、有哪些边界；详细行为仍以对应 Skill、工具实现和官方文档为准。

| 文档 | 职责 |
|---|---|
| [工作流注册表](../.agents/skills/video-production-dispatcher/references/workflow-registry.md) | 选择哪一条主生产工作流 |
| 本目录 | 查找可复用的共享能力和资源 |
| 各 Skill / 工具文档 | 说明具体调用、配置和验收 |
| 运行时查询 | 确认当前账号、模型、音色、依赖和权限 |

TTS、字幕、素材搜索、音频混音、动画和渲染是共享能力，不是新的顶层视频类型工作流。所有工作流最终都要映射到统一的 video-spec 契约。

## 2. 统一登记字段

每项能力使用以下字段登记：

| 字段 | 含义 |
|---|---|
| capability_id | 稳定、唯一的能力 ID |
| 分类 | workflow、text、audio、media、caption、motion、render 或 resource |
| 能解决的问题 | 用户价值和适用范围 |
| 统一入口 | Skill、脚本、CLI 命令或目录路径 |
| 输入与输出 | 主要输入、产物和 metadata |
| 前置条件 | 凭据、授权、依赖、素材或项目状态 |
| 可用性状态 | stable、runtime-query、optional 或 planned |
| 权威来源 | 维护该能力的 Skill、工具或参考文档 |
| 维护责任 | 负责更新规则和兼容性的模块 |

## 4. 阿里云能力专项边界

- qwen-audio-*、cosyvoice-* 和 qwen3-tts-* 使用不同 API 路由，不能混用协议或请求格式。
- 复刻后的音色必须与后续合成使用的 target_model 完全匹配。
- qwen3-tts-flash 是系统音色合成模型，不应作为本地声音复刻模型使用。
- API Key 只能放在根目录 .env.local 或环境变量中，不能写入代码、Markdown、日志、manifest、spec 或聊天记录。
- 模型、voice ID、配额和授权状态以运行时查询为准；本目录不保存账号授权快照。

## 5. 项目资源与目录边界

| 路径 | 角色与边界 |
|---|---|
| assets/<film-slug>/ | 用户输入素材边界；不写入 spec、edit-plan、预览、渲染视频或生成音频 |
| assets/<film-slug>/references/ | 研究资料、来源 URL、日期和摘录；大型媒体默认只记录来源 |
| projects/<project-slug>/ | 独立交付项目，保存 project.json、spec、分镜、工程和运行记录 |
| outputs/<project-slug>/ | 保存递增的 render-vNNN.mp4；不覆盖历史版本 |
| docs/ | 平台、工作流、工具和能力文档；不存放密钥或临时凭据 |

project.json 使用 source_film_slug 关联共享素材；variant_id 只记录候选批次或实验，不自动创建嵌套项目目录。

## 6. 新工作流接入流程

1. 阅读本目录和[工作流注册表](../.agents/skills/video-production-dispatcher/references/workflow-registry.md)，确认现有能力和支持边界。
2. 读取对应权威 Skill 或工具文档，按其入口、前置条件和验收规则调用。
3. 将产物写入项目约定的位置，保留必要的 metadata、来源和版本信息。
4. 只有现有能力确实无法满足时，才新增工具、Skill 或资源；新增后同步补充本目录和测试/文档。
5. 最终映射到统一 video-spec，并经过规格校验、渲染前检查和渲染后产物检查。

## 7. 状态与维护规则

- stable：已有统一入口，并有测试、契约或明确操作文档支撑。
- runtime-query：入口存在，但账号授权、模型、voice、配额或参数必须运行时确认。
- optional：能力可用，但依赖额外登录、模型下载、本机工具或用户选择。
- planned：只有设计、局部实现或尚未注册，不得宣称为原生支持。
- 详细行为以对应 Skill、工具和官方文档为准；本目录只保留摘要。
- 新增或删除统一入口时，必须同步更新路径、状态和维护责任。
- 未在工作流注册表中登记的视频类型，不因底层能力已存在而被视为已实现的顶层工作流。
