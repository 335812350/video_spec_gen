# 新影片资料补全

这份 reference 规定新影片进入 video-spec-director 工作流时的资料检索门槛。它服务于分镜和剪辑决策，不能替代剧本、逐字稿或对本地片源的复核。

## 触发条件

执行完整补全的情况：

- 源影片的 assets/<film-slug>/references/ 尚无最小资料，且该 film-slug 第一次进入工作流；
- 用户明确说“换一部影片”或要求刷新影片资料；
- 现有资料缺少影响剪辑决策的关键事实，且用户要求补全。

同一源影片新建不同的 project-slug 时复用 assets/<film-slug>/references/ 的既有资料，不因项目没有 spec 而重复全量检索。已有影片的普通 spec 迭代也不重复全量检索。增量刷新时保留既有来源记录，只更新发生变化的字段和检索日期。

## 检索顺序

先读本地，再查外部。外部检索必须使用可追溯的联网搜索/浏览器工具；联网不可用时记录 `access_failed`，不能用模型记忆替代检索。搜索时使用片名、别名、上映年份和原文片名组合，避免同名影片串资料。

1. 用户提供的源视频、字幕、脚本、海报、分析 JSON 和说明文件。这些是本项目的素材事实；原始路径和文件名不能被改写。
2. 片方、发行方、电影节、政府或奖项主办方的官方页面和公告。用于确认演职员、上映、发行、奖项和制作机构。
3. 可靠的行业数据库和专业媒体，例如 1905 电影网、中国电影数据信息网。用于补足备案梗概、片长、主创和发行信息，但仍需记录具体页面。
4. 中文和英文维基百科。用于发现别名、角色表、海外发行、票房、奖项、原声带和剧情线索；它是二手/社区编辑来源，不能单独证明争议事实。尽量保存固定版本 `oldid`。
5. 采访、影评和其他专业文章。只用于主题、创作语境和争议点，不将评论观点写成影片事实。

来源不要求全部成功。每次尝试都要在 `film-metadata.json` 的 `research.sources` 中留下记录：

```json
{
  "id": "wikipedia-zh",
  "url": "https://…",
  "retrieved_at": "YYYY-MM-DD",
  "status": "found",
  "source_tier": "secondary",
  "supports": ["plot", "cast", "release"],
  "revision": "oldid=…",
  "notes": "用于线索发现，待一手来源核验"
}
```

`status` 只能是 `found`、`not_found` 或 `access_failed`。页面存在但字段未提供时用 `not_found`；网络、反爬或权限问题用 `access_failed`，不要默默跳过。

## 输出位置与最小内容

只在 `assets/<film-slug>/references/` 写入资料文档；不把外部检索结果写入 `projects/` 或仓库根目录。若目录或目标文件已存在，先读取并合并：保留原内容、原来源和原文件名，只补字段或追加带日期的修订记录，禁止静默覆盖。

- `film-metadata.json`：片名和别名、年份/地区/语言、类型、片长、导演/编剧/制片及主要演员角色、制作/发行机构、上映日期、票房/奖项（带口径和来源）、原声带、关联作品、本地素材与分析文件清单、`research.sources`。
- `film-profile.md`：无剧透 logline、事实卡、主题和语境、内容警示、带“剧透”标题的剧情摘要、待核验清单。
- `story-context.md`：角色关系、起承转合和可检索的故事节点；每个节点标注时间码依据（本地分析、字幕或人工回看）和事实/推断状态。
- 可选 `media-manifest.json`：记录源文件相对路径、大小、哈希、可测得的容器/音视频参数和来源。工具不可用时填 `unknown`，不能从剧情时间戳反推分辨率、帧率或片长。

JSON 写入 UTF-8，并在完成后解析校验。新增文件不得覆盖用户已有文件；需要修订时保留原字段和旧来源，或先明确这是一次刷新。

## 事实分层与剧情写法

至少区分以下层级：

- `user_asset`：用户提供或从本地片源直接测得；
- `official`：片方、发行方、政府、电影节或奖项官方信息；
- `industry`：行业数据库和专业媒体；
- `secondary`：维基百科、影评、采访等二手资料；
- `inference`：根据多个来源或本地画面做出的编辑判断。

无法确认的字段使用 `unknown`、`not_found` 或 `needs_primary_verification`。完整剧情应以自己的话概括关键因果、人物变化和结局，注明“含剧透”；不要长段复制百科、媒体或剧本原文。百科剧情必须在本地视频、字幕或一手资料存在时回查，不能直接当作片方剧本。

## 字幕、逐字稿和 SRT

先检查 `assets/<film-slug>/audio/` 和 `analysis/` 是否已有字幕或逐字稿。没有权威字幕时，把“缺少可核验 SRT”写入待核验清单；不要为了让目录看起来完整而从不明字幕站下载文件。

如果源影片已经内嵌字幕且用户确认满足要求，记录字幕策略为沿用源视频字幕；内嵌字幕已属于画面内容，不需要另生成 SRT。只有需要提取、重排、翻译或重新设计字幕时，才进入下面的转录流程。

如果用户明确要求字幕：

- 优先使用用户提供的 SRT/字幕轨，或从本地片源转录生成，并在文件旁记录工具、语言、时间基准和置信度；
- 外部字幕只能保存为 `candidate`，记录下载 URL、版本、语言、偏移和校验信息，未经逐句对齐不得进入权威资料；
- 不复制或分发无法确认授权的大段字幕文本；无法取得字幕时记录 `not_found` / `access_failed` 和下一步人工校对建议。

## 完成门槛

资料补全完成的定义是：目标目录已确定；本地输入已盘点；优先来源已尝试并逐项记录状态；三个最小文档已生成并能互相引用；缺失和冲突已显式列出；关键事实没有以推测冒充事实。满足这些条件后，才进入 0-1 需求收集或 spec 迭代。
